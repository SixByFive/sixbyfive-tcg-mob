## Context

`components/common/SegmentTabs.js` was designed for 5 profile tabs (including Achievements). It renders left/right overlay bars with chevron arrows for scrolling. With 5 tabs the content overflowed the container, so `canScroll` was `true` and the bars were needed.

After removing Achievements (DEC-0009), only 4 tabs remain. These fit within the container so `canScroll` is `false`. However:

1. The left/right bars were still always rendered (just with `opacity: 0.45` and `pointerEvents: "none"`), visually covering the first and last tab labels.
2. The tabs were left-aligned inside the scroll container, looking off-centre.

## Decision

1. **Hide bars when not needed**: Wrapped both bar `View` elements in `{canScroll && (...)}` — they don't mount at all when tabs fit without scrolling.

2. **Center tabs when not scrollable**: Applied conditional `contentContainerStyle` to the `ScrollView`:
   ```js
   canScroll
     ? { paddingLeft: BAR_W + EDGE_PAD, paddingRight: BAR_W + EDGE_PAD }
     : { flexGrow: 1, justifyContent: "center" }
   ```
   `flexGrow: 1` expands the content container to full width; `justifyContent: "center"` centres the tab row within it.

## Consequences

- Profile tab bar looks correct with 4 tabs — centered, no phantom arrows.
- If tabs are ever added back, `canScroll` will become `true` automatically and bars/padding re-appear.
- The `scrollable` prop still defaults to `true` — passing `scrollable={false}` disables scroll detection entirely.
