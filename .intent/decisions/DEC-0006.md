## Context

The app needs to point at different endpoints for local development (gateway on `10.0.2.2:4010`) vs production. Expo doesn't support per-environment `.env` files natively at build time in the same way web frameworks do. We need a reliable runtime switch.

## Decision

Use a single boolean flag `EXPO_PUBLIC_DEV_MODE` in `app.json`'s `extra` block. `lib/apollo.js` reads this at startup:

```js
const DEV_MODE = process.env.EXPO_PUBLIC_DEV_MODE === "true"
  || Constants.expoConfig?.extra?.EXPO_PUBLIC_DEV_MODE === true;
```

When `true`, the app uses `EXPO_PUBLIC_GRAPHQL_ENDPOINT_LOCAL` and `EXPO_PUBLIC_SOCKET_URL_LOCAL`. When `false`, it uses the prod URLs.

Android emulator uses `10.0.2.2` (not `localhost`) to reach the host machine.

## Consequences

- `EXPO_PUBLIC_DEV_MODE` **must be set to `false`** before every production build.
- The prod URL values (`EXPO_PUBLIC_GRAPHQL_ENDPOINT`, `EXPO_PUBLIC_SOCKET_URL`) currently contain `REPLACE_WITH_PROD_API_URL` as placeholders â€” these must be filled in when the new backend gets a production domain.
- All three files with hardcoded `ASSET_BASE_URL` fallbacks currently reference `backendtcg.sixbyfive.com` (old backend, still live), which is the safe prod fallback until the new backend has a domain.
