## Context

The old backend's `registerExpoPushToken` and `unregisterExpoPushToken` mutations returned an object `{ ok: Boolean!, error: String }`. The mobile app checked `data?.registerExpoPushToken?.ok`.

The new tcg-runtime gateway changes both mutations to return bare `Boolean!`.

## Decision

Update `graphql/push.js` to select bare Boolean (no subfields):

```graphql
mutation RegisterExpoPushToken($token: String!) {
  registerExpoPushToken(token: $token)
}
```

Update the handler in `app/_layout.js`:

```js
const ok = data?.registerExpoPushToken;
if (!ok) { /* handle failure */ }
```

- Simpler response handling â€” no nested `.ok` access.
- If the mutation fails, Apollo returns an error in the errors array (not in the data shape).
- Both register and unregister mutations follow the same pattern.
