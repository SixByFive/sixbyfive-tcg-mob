## Context

The old app used Apollo's `split` link to route messaging operations to a separate GraphQL endpoint (the old WordPress messaging API). This required a custom `isMessagingOperation` predicate that inspected each operation and forwarded it to a different HTTP link.

The new `tcg-runtime` backend exposes a **single unified GraphQL gateway** on port 4010. All operations â€” including messaging â€” go through this one endpoint. There is no separate messaging endpoint.

## Decision

Remove the `split` link and all messaging-split routing logic from `lib/apollo.js`. Simplify to a single routed link:

```js
function buildRoutedLink() {
  const httpLink = DEV_MODE ? devHttpLink : prodHttpLink;
  return authLink.concat(httpLink);
}
```

Also remove `EXPO_PUBLIC_MESSAGING_GRAPHQL_ENDPOINT_LOCAL` from `app.json` (no longer needed).

## Consequences

- All GraphQL operations go to the same endpoint.
- Simpler Apollo client â€” easier to debug and reason about.
- The `split` import from `@apollo/client` is no longer used.
- If messaging is ever split to its own service again, the routing logic must be reintroduced.
