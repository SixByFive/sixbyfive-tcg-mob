## Context

When a new binder is created it has no pages in the database. The binder editor (`app/binder/[id]/edit.js`) showed a local fallback "Page 1" (id: "temp-0", no `rawId`) so the UI looked correct. But when the user tried to add cards, `addCard` in `useBinderActions.js` fell back to the `{ binderId, pageIndex }` path (no `rawId` = no `pageId`), which tried to resolve the pageId from cache then network — both returned empty pages arrays — and threw `"Unable to resolve pageId from binder cache"`.

## Decision

In `hooks/useBinderActions.js`, after both cache and network fetch return empty pages, automatically create the first page via `saveBinderPagesAndSlots` before proceeding:

```js
if (!pages.length) {
  const { data: createData } = await savePagesMut({
    variables: {
      binderId: bId,
      pages: [{ title: "Page 1", layout: "pocket-9", pageOrder: 0, slots: [] }],
    },
  });
  pages = Array.isArray(createData?.saveBinderPagesAndSlots?.pages)
    ? createData.saveBinderPagesAndSlots.pages : [];
}
```

The newly created page's ID is then used for the fast-path `addCardToBinder` mutation.

## Consequences

- First card add on a brand-new binder now succeeds silently without the user needing to manually tap "Add Page".
- Auto-creates a `pocket-9` (3×3) layout page — matches the default template in `BinderOptionsModal`.
- If `saveBinderPagesAndSlots` fails, the error is logged and the original "Unable to resolve pageId" error is re-thrown.
