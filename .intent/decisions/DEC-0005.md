## Context

The old backend's `searchUsers` resolver accepted a `query` variable. Two components (`NewMessageModal.js` and `UserSearchCard.js`) passed `variables: { query: searchText }`. The new tcg-runtime gateway renames this argument to `q`.

## Decision

Update both components to pass `variables: { q: searchText }` and update `SearchUsersDocument` in `graphql/documents.js` to use `$q: String!`:

```graphql
query SearchUsers($q: String!) {
  searchUsers(q: $q) {
    id username avatar bio country createdAt
  }
}
```

## Consequences

- Both `NewMessageModal.js` and `UserSearchCard.js` had their variable key updated.
- The `SearchUsersDocument` in `graphql/documents.js` uses `$q`.
- Using the old `query` variable name silently returns empty results (not an error), so this is a hard-to-spot bug if missed.
