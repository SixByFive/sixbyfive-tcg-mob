## Context

The mobile app was built against the old WordPress-based TCG backend using `@sixbyfive/tcg-binder`, a generated GraphQL client (Apollo codegen output). This package contained all GQL documents and React hook wrappers (`useLoginMutation`, `useMeQuery`, `useSearchCardsLazyQuery`, etc.) for the old schema.

The new backend is `tcg-runtime` â€” a purpose-built Node.js GraphQL gateway. Its schema is different: field names changed, return types changed, and the split messaging endpoint was removed. The generated package cannot be patched to work with the new schema.

## Decision

Replace all `@sixbyfive/tcg-binder` imports with local GQL documents. Create a single file `graphql/documents.js` as the new source of truth for all operation documents.

For React hooks that were previously generated (`useMeQuery`, `useSearchUsersLazyQuery`, `useUserProfileQuery`), create thin shim files in `hooks/` that wrap `useQuery`/`useLazyQuery` with the correct local document.

The old `@sixbyfive/tcg-binder` package remains installed (it's referenced in barrel files) but no screen or component imports from it directly.

## Consequences

- All GQL documents must be hand-maintained. No more codegen.
- Schema changes require manual document updates.
- Hook shims keep call-site changes minimal â€” existing components `import { useMeQuery } from "../../hooks/useMeQuery"` unchanged.
- Barrel files (`graphql/tcg-queries.js`, `tcg-mutations.js`, `tcg-fragments.js`) still re-export from `@sixbyfive/tcg-binder` but nothing imports from them â€” safe to leave.
