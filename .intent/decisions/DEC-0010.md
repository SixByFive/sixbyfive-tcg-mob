## Context

`app.json` originally had `EXPO_PUBLIC_SOCKET_URL_LOCAL: "http://10.0.2.2:4020"`. The realtime Socket.IO service in `tcg-runtime` actually runs on port **4018**, not 4020. This caused `xhr poll error` (HTTP 404) on every socket connect attempt because port 4020 was not listening.

The error appeared as:
```
LOG [socket] connect_error xhr poll error { url: "http://10.0.2.2:4010", status: 404, "Cannot GET /realtime/socket.io/" }
```

(The logged URL showing 4010 was the Metro-cached old bundle — after clearing Metro cache the correct 4018 URL was used.)

## Decision

Update `app.json`:
```json
"EXPO_PUBLIC_SOCKET_URL_LOCAL": "http://10.0.2.2:4018"
```

Also enhanced `lib/realtime.js` connect logging to include `url`, `description`, `context`, and `type` on `connect_error` events for easier future debugging.

Metro bakes `Constants.expoConfig.extra` at bundle time — **requires `npx expo start --clear` after any `app.json` change** to take effect.

## Consequences

- Socket.IO connects successfully in dev when the realtime service is running on port 4018.
- The prod `EXPO_PUBLIC_SOCKET_URL` still contains the `REPLACE_WITH_PROD_API_URL` placeholder — must be updated before a production build.
- `sys-backend` and `sys-messaging` updated to reference port 4018 for the realtime service.
