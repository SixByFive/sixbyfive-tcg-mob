## Context

The achievements feature existed in the mobile app as a profile tab visible on both the own profile (`app/(tabs)/profile.js`) and public profiles (`app/profile/[username].js`). It had a dedicated component (`AchievementsTab`), local GQL query, asset files (badge PNGs), and re-exports across the barrel files.

The feature is not ready for production and was adding dead weight to the bundle.

## Decision

Remove achievements entirely from the mobile app:

- Deleted `components/profile/tabs/AchievementsTab.js`
- Deleted `graphql/GetUserAchievements.query.js`
- Deleted `assets/achievements/` (folder + all PNG assets)
- Removed the "Achievements" tab entry from both profile screens
- Removed `AchievementsTab` import, lazy-load query, state, memos, effects, and render block from `app/profile/[username].js`
- Removed import, tab entry, derived var, and render block from `app/(tabs)/profile.js`
- Removed achievement re-exports from `graphql/tcg-queries.js`, `graphql/tcg-fragments.js`, `graphql/tcg-mutations.js`

## Consequences

- `SegmentTabs` on profiles now shows 4 tabs (Overview, Cards, Binders, Wishlist) instead of 5 — this triggered a layout fix (see DEC-0014).
- The `@sixbyfive/tcg-binder` barrel re-exports for achievement documents are gone; if achievements are re-added they will need new local GQL documents.
- No backend changes required — the `userAchievements` resolver remains on the gateway.
